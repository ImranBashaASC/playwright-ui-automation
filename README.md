# Enterprise Playwright TypeScript Automation Framework

This repository contains a comprehensive, production-ready UI automation framework built with Playwright and TypeScript. It's designed to be scalable, modular, and maintainable, following industry best practices for enterprise-level projects.

## ✨ Features

- **Tech Stack**: Playwright, TypeScript, Node.js
- **Design Patterns**: Page Object Model (POM), Component Object Model, Fixture-based Design
- **Architecture**: Modular, SOLID, DRY, KISS
- **AI-Ready**: Includes interfaces for future integration of AI agents for tasks like self-healing, test generation, and analysis.
- **CI/CD Ready**: Pre-configured workflows for GitHub Actions and Azure DevOps.
- **Containerized**: Docker support for consistent test execution environments.
- **Comprehensive Reporting**: Multiple reporters including HTML, Allure, JUnit, and JSON.
- **Code Quality**: Enforced with ESLint and Prettier.
- **Self-Healing**: A Locator Manager with a priority-based fallback mechanism.
- **Rich Feature Set**: Supports visual testing, accessibility testing, network mocking, multi-user authentication, and much more.

## 🚀 Getting Started

### Prerequisites

- [Node.js](https://nodejs.org/en/) (LTS version recommended)
- [Git](https://git-scm.com/)

### 1. Clone the Repository

```bash
git clone <repository-url>
cd playwright-ui-automation
```

### 2. Install Dependencies

This command installs all the necessary project dependencies defined in `package.json`.

```bash
npm install
```

### 3. Install Playwright Browsers

This command downloads the browser binaries (Chromium, Firefox, WebKit) that Playwright needs to run tests.

```bash
npx playwright install
```

### 4. Environment Configuration

Create a `.env` file in the root of the project by copying the example file.

```bash
cp .env.example .env
```

Now, edit the `.env` file to set your application's base URL and any other environment-specific variables.

```env
# .env
ENV=qa
BASE_URL_QA=https://www.saucedemo.com
ADMIN_USER=standard_user
ADMIN_PASSWORD=secret_sauce
```

## 🧪 Running Tests

The framework comes with a variety of pre-configured npm scripts to run tests.

### Run All Tests

This command runs all tests in headless mode across all configured browsers in parallel.

```bash
npm test
```

### Run Tests with UI (Headed Mode)

To watch the tests execute in a browser window.

```bash
npm run test:headed
```

### Run a Specific Test Suite (e.g., Smoke)

Tests can be tagged with `@Smoke`, `@Regression`, etc. Use the `--grep` flag to run specific suites.

```bash
npm run test:smoke
```

### Run a Single Test File

```bash
npm run test:file tests/e2e/login.spec.ts
```

### Run Tests on a Specific Browser

```bash
npm run test:browser:firefox
```

### Open the Last HTML Report

```bash
npm run report:show
```

### Generate Allure Report

```bash
npm run report:allure
```

## 📈 Reporting

- **HTML Report**: Generated by Playwright. Open with `npm run report:show`.
- **Allure Report**: Provides a rich, interactive report. Generate with `npm run report:allure`.
- **JUnit/JSON**: Available for CI/CD integration, located in the `reports/` directory after a test run.
- **Trace Viewer**: Traces are generated on the first retry of a failed test. These provide a complete, step-by-step view of the test execution.

## 🤖 AI-Ready Architecture

The `/ai` directory contains interfaces for various AI agents. This modular design allows for the future integration of Large Language Models (LLMs) or other AI services to enhance the framework's capabilities without requiring a major architectural overhaul.

**Example Agents:**
- `LocatorHealingAgent`: To dynamically find elements if their primary locators fail.
- `FailureAnalysisAgent`: To analyze test failures and suggest root causes.
- `TestGenerationAgent`: To automatically generate new test cases based on application changes.

## 🐳 Docker Execution

To ensure a consistent environment, you can run the tests inside a Docker container.

### 1. Build the Docker Image

```bash
docker-compose build
```

### 2. Run the Tests

```bash
docker-compose run --rm playwright
```

This will mount the local directory into the container, run the tests, and output the reports to your local filesystem.

## 🤝 Best Practices

- **Use Fixtures for Setup**: Encapsulate setup and teardown logic (like logging in) within custom fixtures.
- **Keep Locators Out of Tests**: Store locators in page/component objects or a dedicated `locators` directory.
- **Write Business-Facing Methods**: Page objects should expose methods that describe user actions (e.g., `loginWithCredentials`), not just wrap Playwright calls.
- **Use Smart Waits**: Avoid fixed waits (`page.waitForTimeout`). Rely on Playwright's auto-waiting and `expect` assertions.
- **Tag Your Tests**: Use tags like `@Smoke`, `@Regression`, `@E2E` to organize and run specific subsets of your tests.
