# Playwright UI Automation Framework

This is an enterprise-grade, scalable, and modular Playwright UI Automation Framework using TypeScript. It's designed to be AI-ready and follows industry best practices for modern web application testing.

## Features

- **Cross-Browser Support**: Chrome, Firefox, WebKit.
- **Parallel Execution**: Run tests in parallel for speed.
- **Page Object Model (POM)**: For maintainable and reusable test code.
- **Component Object Model**: For reusable UI components.
- **Custom Fixtures**: For setting up test-specific states and data.
- **Multiple Reporters**: HTML, Allure, JUnit, JSON.
- **CI/CD Integration**: Ready-to-use pipelines for GitHub Actions and Azure DevOps.
- **Dockerized**: Run tests in a containerized environment.
- **Self-Healing Locators**: Fallback mechanism for more stable tests.
- **Smart Waits**: No fixed waits, uses Playwright's auto-waiting capabilities.
- **Advanced Logging**: Detailed logs using Winston.
- **Data-Driven Testing**: Support for JSON, CSV, and Excel.
- **Bonus Features**: Visual & Accessibility testing, Network Mocking, API helpers, and more.
- **AI-Ready Architecture**: Designed for future integration with AI/ML models for test optimization.

## Tech Stack

- **Automation Tool**: Playwright
- **Language**: TypeScript
- **Package Manager**: npm
- **Framework Pattern**: Page Object Model (POM), Component Object Model, Fixture-Based Design
- **Code Quality**: ESLint, Prettier

## Installation

1.  **Clone the repository:**
    ```bash
    git clone <repository-url>
    cd playwright-ui-automation
    ```

2.  **Install Node.js:**
    Ensure you have the latest LTS version of Node.js installed.

3.  **Install dependencies:**
    ```bash
    npm install
    ```

4.  **Install Playwright browsers:**
    ```bash
    npx playwright install
    ```

## Environment Setup

1.  Create a `.env` file in the root of the project.
2.  Add environment-specific variables to this file. This file is ignored by Git.

    ```env
    # Base URL for the application under test
    BASE_URL=https://ecommerce-playground.lambdatest.io/index.php?route=account/login

    # Environment (dev, qa, uat)
    ENV=qa

    # Credentials
    ADMIN_USERNAME=your-admin-username
    ADMIN_PASSWORD=your-admin-password
    ```

## Execution

The framework provides several npm scripts for running tests with different configurations.

### Run all tests

```bash
npm test
```

### Run tests with specific tags

-   **Smoke Tests**: `npm run test:smoke`
-   **Regression Tests**: `npm run test:regression`
-   **Sanity Tests**: `npm run test:sanity`

### Run tests in different environments

-   **QA Environment**: `npm run test:qa`
-   **DEV Environment**: `npm run test:dev`
-   **UAT Environment**: `npm run test:uat`

### Headed vs. Headless Mode

-   **Headed Mode**: `npm run test:headed`
-   **Headless Mode (default)**: `npm test`

### Other useful commands

-   **Run a single test file**: `npx playwright test tests/e2e/login.spec.ts`
-   **Run tests on a single browser**: `npx playwright test --project=chromium`
-   **Debug tests**: `npm run test:debug`

## Reporting

After test execution, reports are generated in the `reports/` and `allure-results/` directories.

-   **HTML Report**: Open `reports/html/index.html` to see the detailed HTML report.
    ```bash
    npx playwright show-report reports/html
    ```
-   **Allure Report**:
    1.  Generate Allure report data: `npm test` (configured to run by default)
    2.  Serve the report: `npm run allure:report`
-   **JUnit Report**: `reports/junit/results.xml`
-   **JSON Report**: `reports/json/results.json`

## CI/CD

The framework includes pre-configured CI/CD pipelines for:

-   **GitHub Actions**: See `.github/workflows/ci.yml`. The workflow is triggered on push/pull requests to the `main` branch. It installs dependencies, runs tests, and uploads reports as artifacts.
-   **Azure DevOps**: See `azure-pipelines.yml`. This pipeline can be imported into Azure DevOps to achieve similar CI functionality.

## Docker

Run your tests inside a Docker container to ensure a consistent environment.

1.  **Build the Docker image:**
    ```bash
    docker-compose build
    ```

2.  **Run the tests:**
    ```bash
    docker-compose run --rm playwright
    ```
    This command mounts the local directory into the container, runs the tests, and then removes the container. Reports and logs will be available on your local machine.

## Code Quality

-   **ESLint**: A linter to find and fix problems in your TypeScript code. Run it with `npm run lint`.
-   **Prettier**: An opinionated code formatter to ensure consistent code style. Run it with `npm run format`.

## Best Practices

-   **Use POM and Component Model**: Keep your selectors and UI interaction logic separate from your tests.
-   **Avoid Fixed Waits**: Use Playwright's auto-waiting mechanisms like `locator.waitFor()` and web-first assertions.
-   **Use Fixtures**: Abstract away setup and teardown logic to make tests cleaner.
-   **Centralize Locators**: Use the `LocatorManager` for robust and potentially self-healing element selection.
-   **Write Atomic Tests**: Each test should be independent and not rely on the state of previous tests.
-   **Use Tags**: Organize your tests with tags (`@Smoke`, `@Regression`) for flexible test execution.
